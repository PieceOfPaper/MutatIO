# MutatIO

> 먹고, 성장하고, 변이하는 생태계형 실시간 IO 게임.

MutatIO는 모든 플레이어가 작은 기본 생명체로 시작하여 필드의 먹이를 먹고 성장하는 Unity WebGL 기반 IO 게임입니다. 초식 개체가 죽으면 누적 섭취량에 비례한 육식 먹이를 남기며, 이를 계속 섭취한 기본 생명체는 다른 개체를 사냥해야 살아갈 수 있는 포식자로 변이합니다.

현재는 **프리프로덕션 및 핵심 프로토타입 준비 단계**입니다. 온라인 멀티플레이와 게임 규칙 구현은 앞으로 진행합니다. 전투는 몸집 기반 접촉 처치로 구체화했으며, 수치와 세부 판정은 미결정입니다.

## 현재 확정된 방향

| 항목 | 내용 |
| --- | --- |
| 엔진 | Unity 6.3 LTS — 6000.3.26f1 |
| 렌더링·시점 | 2D URP · 탑다운 2D 고정 |
| 주 플랫폼 | 웹 브라우저 — Unity WebGL |
| 입력 | WASD / 방향키 / 좌하단 고정 가상패드 / 터치/마우스 추종 중 선택 |
| 접속 구조 | 라운드에 구속되지 않고 자유롭게 입장·퇴장하는 IO 형태 |
| 시작 상태 | 외형·닉네임·조작 선택 후 작은 초식 생명체로 시작 |
| 핵심 성장 | 먹이 1개 = 1점, 점수로 몸집 계산. 외형 반경과 충돌 반경 동일 |
| 생태 순환 | 먹이 부족 → 죽음과 사체 → 변이 포식자 발생 → 개체 수 변화 |
| 개발 방식 | 기획 문서는 GPT와 갱신하고, 구현은 Codex·Claude Code·직접 작업을 병행 |

## 플레이 흐름

첫 화면에서 캐릭터·닉네임·4가지 이동 방식 선택 → 월드 입장 → 먹이 자동 흡수·성장·변이·접촉 경쟁 → 사망 결과 → 확인 후 첫 화면 복귀.

초식끼리 접촉해도 죽지 않으며, 큰 육식이 작은 초식·육식에 접촉하면 작은 개체가 죽습니다. 육식 사망은 고기를 남기지 않습니다. 성장하면 카메라 범위가 넓어지고 스페이스 또는 모바일 버튼으로 대시를 사용할 수 있습니다. PC 마우스 모드는 클릭 없이 커서를 추종하고 좌클릭으로도 대시합니다. UI 입력은 월드 이동이나 대시에 중복 적용하지 않습니다.

이전 캐릭터·닉네임·조작 선택은 PlayerPrefs로 복원합니다. 이동은 약한 관성과 크기별 속도 감소를 적용하며, 대시는 현재 이동 방향(정지 시 마지막 유효 방향)을 사용합니다.

초식 먹이는 타일 내부에 랜덤 생성하고, 캐릭터 몸체가 덮은 타일은 리젠을 막습니다. 초기 가정은 월드 1000×1000, 타일 5×5이며 타일당 최대 n개입니다. 흡수 거리는 몸 반경에 고정 거리를 더합니다. 굶주림으로 점수·몸집을 줄이지 않고 포만 소진 시 사망합니다.

육식은 초식 먹이를 먹지 못하고 밀어내며, 이동한 먹이는 최초 생성 타일에 귀속됩니다. 시간당 허기 감소율은 몸집·역할과 무관하게 동일하지만, 몸집이 커질수록 먹이당 포만 회복량이 감소해 생존에 더 많은 먹이가 필요합니다. 변이에 필요한 고기량도 몸집에 따라 증가하도록 조절합니다. 초식이 고기를 먹으면 변이 게이지와 피드백이 발생하고, 게이지는 시간에 따라 줄어 0에서 숨겨집니다. 동일 크기 접촉과 작은 육식·큰 초식 접촉은 처치가 발생하지 않으며, 초식끼리는 서로 밀립니다.

처치 가능한 역할 조합에서는 점수가 조금이라도 높으면 우위이며, 같은 처리 단계에서는 섭취·성장·변이를 먼저 반영한 후 접촉을 판정합니다.

캐릭터는 원형 몸체에 귀·눈 등의 장식 차이를 줍니다. 아트 확정 전 기본 색은 초식 청록(#4CC9F0), 육식 보라(#B56EFF)로 정리했습니다.

카메라는 맵 끝에서 멈추며, 몸집별 시야는 화면의 짧은 변을 기준으로 확보합니다. 긴 변은 더 넓게 보여주고 월드·캐릭터 비율은 유지합니다.

이 내용은 기획 목표이며 구현 완료 상태가 아닙니다.

## 시작하기

### 필요 환경

- Unity Hub
- Unity Editor **6000.3.26f1**
- 해당 버전의 **WebGL Build Support**
- .NET SDK **10.0** — 서버 빌드·실행
- Git
- 선택: Unity CLI와 Unity Pipeline

### 프로젝트 열기

```bash
git clone https://github.com/PieceOfPaper/MutatIO.git
cd MutatIO
```

Unity Hub에서 저장소의 `Client/` 폴더를 프로젝트로 추가한 뒤 `6000.3.26f1`로 여십시오.

현재 시작 씬은 `Client/Assets/Scenes/SampleScene.unity`입니다. 네트워크 확인용 씬은 `Client/Assets/MutatIO/Scenes/NetworkTest.unity`, 로컬 프로토타입 씬은 `Client/Assets/MutatIO/Scenes/Prototype.unity`입니다.

### Unity CLI 연결

이 프로젝트에는 `com.unity.pipeline` `0.8.0-exp.1`이 포함되어 있습니다. Unity Editor가 프로젝트를 연 상태에서 저장소 루트에서 다음 명령으로 연결 가능한 명령을 확인합니다.

```bash
unity command --project-path "$(pwd)/Client"
```

연결 후에는 먼저 에디터 상태와 콘솔 오류를 확인합니다.

```bash
unity command --project-path "$(pwd)/Client" editor_status
unity command --project-path "$(pwd)/Client" console_status
unity command --project-path "$(pwd)/Client" console --level error --tail 20
```

CLI와 패키지 버전에 따라 명령이 달라질 수 있으므로 자동화 전에 항상 명령 목록을 확인하십시오. Unity Pipeline은 실행 중인 Editor에 로컬 HTTP API로 연결하며 프로젝트 경로를 이용한 자동 탐색을 지원합니다.

### 서버 실행

```bash
dotnet run --project Server/src/MutatIO.Server --launch-profile http
```

`http://localhost:5080/health`에서 상태를 확인할 수 있고, 게임 연결은 `ws://localhost:5080/ws`입니다. 아직 게임 메시지는 처리하지 않습니다.

서버 테스트:

```bash
dotnet test Server/MutatIO.Server.slnx
```

### 클라이언트–서버 연결 확인

1. 위 명령으로 서버를 실행합니다.
2. Unity에서 `Client/Assets/MutatIO/Scenes/NetworkTest.unity`를 열고 Play합니다.
3. 화면 왼쪽 위에 `State: Connected`와 RTT가 표시되면 정상입니다.

Unity EditMode 테스트(Test Runner 또는 CLI)에는 실제 서버에 접속하는 통합 테스트(`Integration` 카테고리)가 포함되어 있습니다. 서버가 실행 중이 아니면 이 테스트는 건너뜁니다. 서버 주소는 환경 변수 `MUTATIO_SERVER_URL`로 바꿀 수 있습니다.

```bash
unity command --project-path "$(pwd)/Client" run_tests --mode EditMode
```

## 현재 실행 및 검증 범위

아직 게임플레이 대부분과 자동화된 빌드·테스트 파이프라인은 준비되지 않았습니다. 현재 구현된 것은 클라이언트–서버 연결과 Ping/Pong RTT 측정, 로컬 이동·대시와 네 가지 조작 입력, 맵 경계·초식 먹이 리젠·자석 흡수·성장·카메라 줌, 포만 감소·굶주림 사망·결과 화면·첫 화면 복귀, 첫 화면의 외형·닉네임·조작 선택과 PlayerPrefs 저장·복원(로드맵 M1~M5), 로컬 봇 플레이어, 고기 드롭·변이·접촉 처치 생태계(M6)입니다.

### 로컬 프로토타입 확인

1. Unity에서 `Client/Assets/MutatIO/Scenes/Prototype.unity`를 열고 Play합니다. 서버는 필요 없습니다. 첫 화면에서 외형(원형 몸체에 귀·눈·표정 장식이 다른 placeholder 4종)·닉네임·조작 방식(`WASD` / `Arrows` / `Pad` / `Mouse`)을 고르고 `PLAY`로 입장합니다. 선택은 입장할 때 저장되어 다음 첫 화면과 다음 실행에서 복원됩니다.
2. Game 뷰를 클릭해 포커스를 줍니다. 포커스가 없으면 키보드·마우스 입력이 게임에 전달되지 않습니다.
3. 조작 방식은 첫 화면에서만 바꿉니다. 오른쪽 위 `Feed +20` / `Feed +200`은 먹이를 먹은 것처럼 섭취량을 더하고, `Starve`는 포만을 거의 비우는 개발용 버튼입니다.
4. 대시는 스페이스, 오른쪽 아래 `DASH` 버튼, `Mouse` 모드의 월드 좌클릭입니다. 왼쪽 위에 닉네임·외형·모드·점수·몸집·포만·속도·대시 상태·초식 먹이 수·현재 좌표가 표시됩니다.
5. 맵은 1000×1000이고 5×5 격자 칸(초식 리젠 타일)마다 초록 먹이가 하나씩 리젠됩니다. 먹이에 다가가면 끌려와 자동으로 섭취되고(1개 = 1점), 점수·몸집이 늘며 이동속도가 줄고 카메라가 넓어집니다. 몸이 덮은 칸에는 먹이가 다시 생기지 않습니다. 붉은 선이 맵 경계이며 맵 끝에서는 카메라가 멈춥니다.
6. 포만은 시간이 지나면 줄고 초식 먹이를 먹으면 회복됩니다. 몸집이 클수록 먹이 하나의 회복량이 줄어듭니다. 0이 되면 사망하고 `GAME OVER`와 점수가 표시되며, `OK`로 첫 화면에 돌아가 다시 입장하면 작은 초식 생명체로 시작합니다.
7. 월드에는 나를 포함해 5명이 유지됩니다. 영문 이름이 붙은 봇 4명이 맵 중앙 근처에 입장해 먹이를 찾아다니고, 봇이 죽으면 3~10초 뒤 새 봇이 들어옵니다. 오른쪽 위 `Role`은 변이를 기다리지 않고 내 역할을 초식·육식으로 바꾸는 개발용 버튼입니다(점수가 높은 육식이 되면 초식 봇이 도망칩니다). `Bot Lv -` / `Bot Lv +`는 봇 수준을 0~1 사이에서 0.2씩 바꾸며, 0에 가까우면 봇이 먹이를 거의 찾지 않아 굶어 죽습니다. 왼쪽 위에 봇 수·대기 수·수준과 봇별 행동(`Wander`/`Forage`/`Flee`/`Chase`)·점수·포만이 표시됩니다.
8. 초식이 죽으면 점수의 절반만큼 붉은 고기가 흩어집니다. 초식이 고기를 먹으면 몸이 붉게 깜빡이고 몸 아래 보라색 변이 게이지가 차며, 게이지는 시간이 지나면 줄어듭니다. 가득 차면 육식(보라)이 되어 초식 먹이를 먹지 못하고 밀어내며, 고기와 사냥으로만 살아갑니다. 점수가 더 높은 육식에 닿으면 죽고, 결과 화면에 `Starved` 또는 `Eaten by 이름`이 표시됩니다. 초식끼리는 서로 밀립니다. `Meat x5`는 내 주변에 고기 5개를 떨어뜨리는 개발용 버튼입니다.
9. 수치는 Play 중 `Prototype` 오브젝트의 `World Simulation Runner`(이동·성장·먹이·허기·변이·접촉·봇)와 `Main Camera`의 `World Camera Controller`(줌) 인스펙터에서 바꿀 수 있습니다. 두 컴포넌트는 Play 시 추가되므로 Play를 끝내면 값이 기본값으로 돌아가고, 맵·타일 크기는 시작 시에만 적용됩니다. 모두 임시값입니다.

기능을 추가할 때는 최소한 다음을 확인해야 합니다.

1. Unity 컴파일 오류가 없는지 확인
2. 관련 EditMode 또는 PlayMode 테스트 실행
3. 변경한 씬을 Play Mode에서 직접 확인
4. 웹 관련 변경은 WebGL 빌드에서 확인
5. 구현과 기획이 달라졌다면 관련 문서와 결정 기록 갱신
