# MutatIO 게임 기획서

- 문서 상태: 플레이 흐름과 기본 규칙 구체화
- 마지막 갱신: 2026-10-17
- 기준 저장소 커밋: 7a450dfa3a2b4798bae1747ab380d14d9104a866
- 목적: 코딩 에이전트와 사람이 공유하는 게임 구현 기준

이 문서의 규칙은 구현 목표이며 구현 완료를 뜻하지 않습니다. **확정**, **제안**, **미결정**을 구분합니다. 미결정 규칙은 [미결정 기획 항목](OPEN_DESIGN_QUESTIONS.md), 테스트로 조정할 수치·곡선은 [밸런스 데이터 목록](BALANCE_PARAMETERS.md)에서 관리하고, 기존 규칙의 변경 이유는 [결정 기록](DECISIONS.md)에 남깁니다.

## 1. 게임 개요

모든 플레이어가 작은 초식 생명체로 시작해 먹으며 점수와 몸집을 키우는 생태계형 실시간 IO 게임입니다. 초식 생명체가 죽으면 그동안 먹은 양에 비례한 육식 먹이가 생성됩니다. 이를 일정량 먹은 초식 생명체는 육식 생명체로 변이하여 자신보다 작은 다른 생명체를 접촉으로 처치할 수 있습니다.

먹지 않으면 굶어 죽고, 성장할수록 주변에 위협이 되거나 가치 있는 먹잇감이 됩니다. 월드는 고정된 라운드 시작 없이 운영되며 누구나 중간에 들어오고 나갈 수 있습니다.

## 2. 용어와 외형

| 용어 | 의미 |
| --- | --- |
| 초식 생명체 | 모든 플레이어가 처음 시작하는 상태. 기존 문서의 기본 생명체 |
| 육식 생명체 | 육식 먹이를 일정량 섭취해 변이한 상태. 기존 문서의 포식자 |
| 초식 먹이 | 필드에 주기적으로 생성되는 초록색 자원. 기존 문서의 기본 먹이 |
| 육식 먹이 | 초식 생명체 사망 시 생성되는 붉은색 자원. 기존 문서의 생체 물질 |
| 포만 게이지 | 남은 생존 여유를 표시하는 게이지. 시간이 지나면 감소하고 먹으면 회복 |
| 섭취량·점수 | 이번 생에 실제 섭취 완료한 먹이 개수. 먹이 1개당 1점 |
| 몸집 | 점수에서 계산되는 원형 반경. 외형 반경과 충돌 반경이 동일하며 독립 질량 자원은 두지 않음 |

초식·육식은 게임 역할을 설명하는 작업용 명칭입니다. 최종 세계관은 인간이 아닌 외계 생명체·미생물 등의 방향을 선호하며 아직 확정하지 않았습니다.

### 캐릭터 선택과 역할 표시 — 확정

- 입장 전에 캐릭터 외형을 선택합니다. 초식·육식 역할을 선택하는 과정은 아닙니다.
- 초식과 육식은 색으로 구분합니다. 정확한 캐릭터 색상은 미결정입니다.
- 캐릭터 바리에이션은 색보다 형태 차이를 중심으로 구성합니다.
- 월드의 캐릭터는 원형을 기본으로 표시합니다.
- 원형 표현 안에서 실루엣·표면·눈·장식 등의 차이를 어떻게 줄지는 미결정입니다.
- 캐릭터 선택에 따른 능력치 차이는 확정된 기능이 아닙니다.

## 3. 전체 플레이 흐름

```text
첫 화면: 캐릭터 선택 + 닉네임 입력 + 4가지 조작 중 선택
                ↓
작은 초식 생명체로 월드 입장
                ↓
이동 → 먹이 자동 흡수 → 점수·몸집 증가
                ↓
육식 먹이 누적 섭취 시 육식 생명체로 변이
                ↓
먹이 경쟁·대시·접촉 판정·굶주림
                ↓
사망 → 이번 플레이 결과 표시
                ↓
확인 버튼 → 첫 화면으로 복귀
```

캐릭터·닉네임·조작 선택은 같은 첫 화면에 배치합니다. 사망 직후 자동으로 월드에 부활하지 않으며, 첫 화면에서 다시 입장할 때 작은 초식 생명체로 시작합니다.

## 4. 입장 화면과 조작 선택

### 입장 준비 — 확정

- 캐릭터 외형을 선택합니다.
- 닉네임을 입력합니다.
- 이동 조작 방식을 선택한 뒤 월드에 진입합니다.
- 모든 플레이어는 같은 작은 초식 상태로 시작합니다.
- 계정 생성이나 로그인은 현재 확정된 입장 조건이 아닙니다.

### 화면 배치 — 확정

캐릭터 선택·닉네임 입력·조작 선택·입장 버튼을 같은 첫 화면에 배치합니다. 별도의 조작 선택 화면을 필수 단계로 만들지 않습니다.

### 이동 조작 네 가지 — 확정

첫 화면에서 다음 네 가지를 개별 선택지로 제공합니다. WASD와 방향키는 하나로 묶지 않습니다.

| 선택지 | 이동 입력 | PC 대시 |
| --- | --- | --- |
| WASD | W 위 / A 왼쪽 / S 아래 / D 오른쪽 | 스페이스 |
| 방향키 | 위 / 왼쪽 / 아래 / 오른쪽 방향키 | 스페이스 |
| 가상패드 | 화면 좌측 하단 고정 가상 조이스틱 | 키보드 사용 시 스페이스 |
| 터치/마우스 추종 | PC는 클릭 없이 커서 방향 추종, 모바일 터치 세부 동작은 아래 참조 | 좌클릭 또는 스페이스 |

모바일에서는 화면 내 대시 버튼을 사용합니다. 네 가지 선택지가 같은 이동·관성·속도·대시 규칙을 사용해야 합니다. 기기에서 사용할 수 없는 입력의 안내 및 최초 기본 선택은 미결정입니다.

### 포인터 이동과 Snake.io 레퍼런스 — 조사 결과 및 제안

공식 자료에서 확인된 내용:
- Snake.io PC는 마우스를 통한 추종형 이동과 WASD·방향키를 제공합니다.
- PC 좌클릭 또는 스페이스를 누르고 있는 동작은 부스트입니다.
- 모바일은 Joystick / Arrow / Follow 옵션을 제공합니다.

따라서 Snake.io PC의 마우스 조작을 '좌클릭한 목적지까지 이동'으로 동일시하지 않습니다. 공식 문서만으로는 터치 해제 후 이동, 캐릭터 중심에서의 정지, 카메라 이동에 따른 목표 갱신을 확인하지 못했습니다. 실기 관찰 결과인 것처럼 문서화하지 않습니다.

PC 마우스 모드는 **Snake.io형 마우스 추종으로 확정**합니다.
- 마우스 버튼을 누르지 않아도 커서 방향을 따라 이동합니다.
- 좌클릭을 해제해도 마우스 추종 이동은 유지합니다.
- 최초 클릭한 월드 좌표를 고정 목적지로 저장하지 않습니다.
- 좌클릭은 이동 시작 입력이 아니라 대시 입력입니다. 기존 스페이스 대시도 유지합니다.
- 캐릭터 중심 근처에서의 처리, 카메라 이동에 따른 좌표 갱신의 세부 규칙은 여전히 미결정입니다.

네 번째 선택지의 설명은 PC에서는 '마우스 추종', 모바일에서는 '터치'로 구분합니다. UI의 최종 표시 문구는 미결정입니다.

모바일은 다음 동작을 **테스트 제안(미승인)**으로 유지합니다. 월드 영역을 누르는 동안 화면상 캐릭터에서 현재 터치 방향으로 이동 입력을 갱신하고, 해제 또는 중심 데드존에서는 입력을 0으로 한 뒤 관성 감속합니다. PC의 클릭 없는 추종과 모바일 터치를 같은 입력 유지 조건으로 묶지 않습니다.

출처와 확인하지 못한 조건은 [조작 레퍼런스 조사](INPUT_REFERENCE.md)에 기록합니다.

### 이동 감각 — 방향 확정, 수치는 테스트

- 입력 방향을 향해 선회하는 별도의 회전속도 제한을 두지 않습니다.
- 이동에는 약한 관성을 넣어 가속·감속과 방향 전환에 약간의 미끄러짐을 줍니다.
- 관성에 의한 속도 벡터 변화와 캐릭터의 회전 제한을 별개의 기능으로 취급합니다. 제한된 회전 반경을 추가하지 않습니다.
- 몸집이 커질수록 이동속도가 완만하게 감소하도록 합니다.
- 크기별 속도 곡선, 최소 속도, 가속·감속 강도는 플레이 테스트로 조정합니다.

속도 감소의 의도는 큰 개체의 접촉 우위와 넓은 시야를 보완하고 작은 개체의 회피 여지를 확보하는 것입니다. [밸런스 데이터 목록](BALANCE_PARAMETERS.md)에 조정 항목을 관리합니다.

### 이전 선택 저장 — 확정

- 선택 캐릭터, 닉네임, 네 가지 조작 중 선택한 모드를 PlayerPrefs에 저장합니다.
- 첫 화면 복귀와 브라우저 재실행 시 이전 정보를 불러옵니다.
- 저장값이 없거나 사용할 수 없으면 기본 선택으로 복구합니다. 최초 기기별 기본 선택은 미결정입니다.
- 캐릭터는 안정적인 식별자로, 조작 모드는 표시 문자열과 분리된 값으로 저장합니다.
- 입장 시 확정된 정보를 저장하는 방식을 기본으로 하며 매 프레임 저장하지 않습니다.
- 이는 이전 선택 복원용입니다. 살아 있던 캐릭터·점수·육식 상태를 이어서 불러오는 기능은 아닙니다.

### UI와 월드 입력 분리 — 확정

'입력 분리'는 버튼 조작 때문에 의도하지 않은 이동이 발생하지 않게 한다는 뜻입니다.
- 설정 버튼을 누른 클릭/터치는 월드 이동 목표로 사용하지 않습니다.
- 조이스틱으로 이동하면서 다른 손가락으로 대시를 눌러도 원래 이동 입력을 유지합니다.
- 터치/포인터다운 모드에서는 대시 버튼을 누른 손가락으로 이동 목표를 바꾸지 않습니다.
- 이동에 사용 중인 터치와 UI 버튼 터치를 구분해 관리합니다.
- PC 마우스가 설정 등 UI 위에 있을 때 해당 UI의 포인터 위치로 새 이동 방향을 갱신하지 않습니다. UI 클릭은 월드 대시로도 중복 처리하지 않습니다.

UI 입력으로 새 이동 방향을 만들지 않는 것은 확정입니다. UI 위에서 기존 방향을 유지할지 감속할지, 설정 창을 열 때 기존 이동을 멈출지 등은 별도 미결정입니다.

## 5. 월드 화면과 HUD — 확정

| 위치 | 표시 |
| --- | --- |
| 화면 좌측 상단 | 점수 랭킹 |
| 화면 우측 상단 | 각종 설정 버튼 |
| 각 캐릭터 머리 위 | 해당 캐릭터의 닉네임과 남은 포만 게이지 |
| 화면 좌측 하단 | 가상패드 모드의 고정 가상 조이스틱 |
| 모바일 조작 영역 | 화면 내 대시 버튼. 위치는 미결정 |

포만 게이지는 가득 찰수록 생존 여유가 많고 시간이 지나면 줄어드는 방향으로 표현합니다. 본인뿐 아니라 다른 캐릭터의 닉네임과 게이지도 표시합니다.

랭킹의 표시 인원, 동점 처리, 설정 항목, UI 겹침 처리, 대시 버튼 위치는 미결정입니다.

## 6. 먹이·점수·성장

### 초식 먹이 생성 — 규칙 확정, 크기는 초기 가정

- 월드를 타일로 나누고 타일별로 초식 먹이를 관리합니다.
- 초기 가정은 월드 1000×1000, 타일 5×5입니다. 가로·세로 각각 200개, 총 40,000타일입니다.
- 각 타일에는 초식 먹이가 최대 n개까지만 존재할 수 있습니다. n과 리젠 주기는 밸런스 데이터입니다.
- 생성 위치는 해당 5×5 타일 내부에서 랜덤으로 정합니다. 격자 중심에 고정 생성하지 않습니다.
- 리젠 시점에 타일 위에 초식 또는 육식 캐릭터가 있으면 그 타일에서는 생성하지 않습니다.
- 캐릭터 중심이 타일 안에 있는지만 검사하지 않습니다. 원형 몸체가 타일 영역을 덮고 있으면 생성이 차단됩니다.
- 큰 캐릭터가 여러 타일을 덮으면 그 타일들 모두에서 리젠하지 않습니다.
- 기존 먹이를 캐릭터가 덮었다고 제거하는 규칙은 아닙니다. 이 조건은 새 먹이 리젠에만 적용합니다.
- 타일 상한과 점유 조건을 만족할 때만 생성합니다. 별도의 서버 인원별 공급 보정은 현재 확정 범위에 포함하지 않습니다.

초기 가정에서 타일 상한만 고려한 초식 먹이 총 최대치는 40,000×n개입니다. 캐릭터 점유 등으로 실제 개수는 더 적을 수 있습니다. 월드·타일 크기는 [밸런스 데이터 목록](BALANCE_PARAMETERS.md)에 초기값으로 기록하며 최종 밸런스로 고정하지 않습니다.

### 육식 먹이 생성 — 확정

- 육식 먹이는 붉은색이며 초식 생명체가 죽었을 때만 생성됩니다.
- 생성량은 죽은 초식이 이번 생에 실제 먹은 먹이 개수, 즉 점수에 비례합니다.
- 육식 생명체가 죽어도 고기를 남기지 않습니다.
- 육식 먹이는 초식 먹이의 주기적 타일 리젠과 별도입니다. 초식 먹이의 타일당 n개 상한을 자동 적용하지 않습니다.
- 최초 포식자를 위한 초기 사체나 필수 NPC를 별도로 배치하지 않습니다.

### 자석 흡수 — 확정

- 먹이가 몸 표면에서 고정 거리 안에 들어오면 자석처럼 당겨집니다.
- 몸 크기에 비례해 흡수 여유 거리를 배수로 키우지 않습니다.
- 중심 기준 흡수 거리 = 캐릭터 몸 반경 r + 고정 흡수 거리 a입니다.
- 예: a=1이면 몸 반경 10의 흡수 거리는 11, 몸 반경 20은 21입니다.
- 이 예시는 거리 관계 설명이며 a의 확정 밸런스값은 아닙니다.
- 처리상 먼저 유효 흡수 범위에 근접한 캐릭터가 먹이의 흡수 대상을 선점합니다.
- 동일 처리 시점에 여러 캐릭터가 들어오면 처리 순서상 먼저 판정된 유효 대상 하나에 배정합니다. 한 먹이를 여러 캐릭터가 중복 획득하지 않습니다.
- 별도 먹기 버튼 없이 자동 흡수하며, 실제 섭취 완료 때만 먹이를 제거하고 점수·포만 회복·변이 누적을 한 번 적용합니다.

흡수 거리 판정은 먹이 위치와 캐릭터 중심 사이 거리를 기준으로 설명합니다. 흡수 속도와 섭취 완료 거리는 밸런스 데이터에서 관리합니다.

### 흡수 중단 — 확정

- 흡수 대상 캐릭터가 사망·이탈·변이하면 진행 중인 흡수를 취소합니다.
- 먹이는 취소 순간의 현재 위치에 남습니다. 최초 생성 위치로 되돌리지 않습니다.
- 아직 먹은 것이 아니므로 점수·포만 회복·변이 누적을 지급하지 않습니다.
- 먹이를 삭제하지 않고 대상 선점을 해제하여 다시 유효한 캐릭터가 흡수할 수 있게 합니다.
- 중단 위치는 바뀌지 않지만 다른 캐릭터의 흡수 대상이 되면 다시 움직일 수 있습니다.

흡수로 타일을 넘은 먹이의 타일 개수 귀속과 리젠 상한 계산 방식은 구현 전 결정할 규칙으로 남깁니다.

### 점수·몸집·충돌 — 확정

- 먹은 양의 단위는 **먹이 개수**입니다. 초식·육식 먹이 모두 1개 섭취 완료 시 1점입니다.
- 먹이 종류별 포만 회복이나 변이 누적은 달라질 수 있지만, 점수 가중치는 별도로 두지 않습니다.
- 점수와 별개로 감소·증가하는 현재 질량 자원을 만들지 않습니다.
- 몸집은 점수에서 계산합니다. 초기 크기와 성장 곡선은 밸런스 데이터로 조정합니다.
- 원형 캐릭터의 **외형 반경 = 충돌 반경 = 몸집 반경**입니다. 지름은 이 값의 두 배입니다.
- 굶주림은 몸집이나 점수를 소모하는 과정이 아닙니다. 먹지 못해 포만 게이지가 소진되면 사망합니다.
- 처치 자체의 별도 점수는 두지 않고 남은 먹이를 실제로 먹어 점수를 얻습니다.

먹이의 조각 수는 곧 획득 가능한 점수량에도 영향을 줍니다. 사망 드롭의 환원율과 조각 분배를 조정할 때 이 관계를 함께 검증합니다.

## 7. 허기와 변이

### 허기 — 확정

- 시간이 지나면 남은 포만 게이지가 감소하고 먹으면 회복합니다.
- 포만 게이지가 소진되면 사망합니다.
- 굶주림으로 점수나 몸집을 깎지 않고, 별도의 질량 연소·체력 감소 단계를 추가하지 않습니다.
- 감소율과 회복량은 밸런스 데이터에서 관리합니다. 몸집·역할별 감소율 적용 여부는 아직 미결정입니다.

### 육식화 — 기존 방향 유지

- 초식 생명체도 육식 먹이를 먹을 수 있습니다.
- 초식 상태에서는 육식 먹이의 허기 회복 효율이 낮으며, 최초 아이디어는 육식 상태에서 먹을 때의 절반 효율입니다.
- 육식 먹이를 일정량 먹으면 육식 생명체로 변이합니다.
- 변이하면 색을 통해 역할 변경을 구분할 수 있어야 합니다.

변이 임계치는 밸런스 데이터로 관리합니다. 변이 누적 수치 감소 여부, 전환 시점·예고 연출, 육식 상태의 초식 먹이 섭취 가능 여부는 미결정입니다. 독립 질량이나 점수와 무관한 전환 질량 배율을 추가하지 않습니다.

## 8. 접촉 전투 — 확정

별도 공격 버튼 대신 캐릭터 간 접촉과 상대적 몸집으로 사망을 판정합니다.

| 접촉 조합 | 결과 |
| --- | --- |
| 초식 ↔ 초식 | 접촉으로 사망하지 않음 |
| 큰 육식 ↔ 작은 초식 | 초식 사망 |
| 작은 육식 ↔ 큰 초식 | 육식이 초식을 죽이지 못함. 육식 사망 여부는 미결정 |
| 큰 육식 ↔ 작은 육식 | 작은 육식 사망 |
| 동일 몸집이 포함된 육식 접촉 | 결과 미결정 |

- 초식의 사망으로 생성된 먹이는 별도로 흡수하여 점수를 얻습니다.
- 접촉 처치가 곧 즉시 섭취를 뜻하지는 않습니다.
- 접촉은 보이는 원형과 동일한 반경으로 판단합니다. 초식끼리의 밀침·통과 여부와 동시 접촉 처리 순서는 미결정입니다.
- 크기 우위에 필요한 최소 차이 또는 비율 역시 미결정입니다.

## 9. 카메라 — 확정

- 내 캐릭터가 커질수록 카메라가 보여주는 월드 영역도 넓어집니다.
- 성장이 캐릭터를 화면 밖으로 밀어내지 않도록 설계합니다.
- UI는 월드 카메라의 표시 범위와 별개로 화면 기준 위치를 유지합니다.

정확한 시점, 줌 곡선, 최대 표시 범위, 보간 속도와 화면 비율별 처리 기준은 미결정입니다.

## 10. 대시 — 확정

- 캐릭터는 순간적으로 빠르게 이동하는 대시를 사용할 수 있습니다.
- 키보드는 스페이스 키로 사용합니다.
- 모바일은 화면 내 대시 버튼으로 사용합니다.
- 대시 후에는 짧은 재사용 대기시간이 있습니다.

- 움직이는 중에는 현재 이동 방향으로 대시합니다.
- 정지 중에는 마지막 유효 이동 방향으로 대시할 수 있습니다.
- PC 마우스 추종 모드에서는 월드 영역 좌클릭으로 대시합니다. 기존 스페이스 대시도 유지합니다.
- UI 버튼 좌클릭은 월드 대시를 발생시키지 않습니다.
- 입장 후 아직 유효 이동 방향이 없는 경우의 처리와 대시 중 방향 변경 허용 여부는 미결정입니다.
- 좌클릭을 계속 누를 때 최초 한 번만 사용되는지, 쿨타임마다 반복되는지는 미결정입니다. Snake.io의 지속 부스트로 자동 변경하지 않습니다.

배율·지속시간·쿨타임·비용 수치는 [밸런스 데이터 목록](BALANCE_PARAMETERS.md)에서 테스트로 결정합니다. 대시 비용을 점수·허기 중 어디에서 소비할지, 비용이 없을지와 대시 중 접촉 판정 변화는 별도 규칙 결정 대상입니다.

## 11. 사망과 결과 — 확정

- 사망하면 해당 생의 플레이를 종료하고 결과 화면을 표시합니다.
- 결과 화면에는 이번 플레이에서 얼마나 모았는지, 즉 최종 획득 점수·누적 섭취 성과를 확인할 수 있어야 합니다.
- 확인 버튼을 누르면 캐릭터 선택과 닉네임 입력이 있는 첫 화면으로 돌아갑니다.
- 다시 입장하면 작은 초식 생명체로 시작합니다.

생존 시간·최고 순위·처치 수 등 추가 결과 항목과 기록의 영구 저장 여부는 미결정입니다. '전적'이라는 표현만으로 계정별 영구 기록 시스템을 구현하지 않습니다.

## 12. 생태계 순환과 검증 주의점

```text
초식 입장 → 초식 먹이 섭취·성장 → 자원 경쟁
  → 초식 사망 → 붉은 먹이 발생 → 초식의 고기 섭취·변이
  → 큰 육식의 접촉 처치 → 초식 감소
  → 육식의 먹이 경쟁·접촉 사망·굶주림
  → 결과 확인 후 첫 화면 → 다시 초식으로 입장
```

이는 의도하는 순환이며 자연적으로 균형을 보장하는 것은 아닙니다. 특히 육식은 고기를 남기지 않으므로 육식 간 전투는 먹이 확보보다 경쟁자 제거의 의미를 가집니다. 초식 감소 시 육식 먹이의 공급이 끊기는 속도를 테스트해야 합니다.

## 13. 아직 확정하지 않은 확장 기능

계정, 영구 성장, 시즌, 수익화, 스킨 능력, 파티, 진화 트리, 필수 AI, 여러 맵, 관전·리플레이는 확정 범위에 포함하지 않습니다.
