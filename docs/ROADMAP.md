## Phase 1 — 로컬 핵심 수직 슬라이스

온라인 기능 없이 핵심 순환이 재미있는지 빠르게 확인합니다.

### 진행 원칙 — 2026-10-17 사용자 승인

- 게임 규칙은 처음부터 `Shared/`의 순수 C# 시뮬레이션으로 작성하고, 로컬 슬라이스에서는 클라이언트가 이를 직접 실행합니다. Phase 3에서 서버가 같은 코드로 권위 판정을 합니다.
- 시뮬레이션은 `dt`를 받아 진행하며 고정 틱을 정하지 않습니다(서버 틱은 미결정).
- 수치는 모두 [밸런스 데이터 목록](BALANCE_PARAMETERS.md)의 항목 ID와 대응하는 설정 데이터의 **임시값**입니다.
- 단계마다 막히는 미결정 규칙은 아래 **임시안**으로 구현해 플레이로 확인합니다. 임시안은 확정 규칙이 아니며 [미결정 기획 항목](OPEN_DESIGN_QUESTIONS.md)에 그대로 남깁니다.

### 단계 순서

| 단계 | 내용 | 확인할 가설 | 임시안 |
| --- | --- | --- | --- |
| M1. 이동 코어 (`Shared/`) | 장치 독립 `PlayerCommand`(이동 벡터·대시), 약한 관성, 크기별 속도 감소, 대시·쿨타임, 마지막 유효 방향 | — | 첫 이동 전 대시 무시, 대시 비용 없음, 정지 판정 임계값 임시값 |
| M2. 입력 계층 (`Client/`) | WASD·방향키·좌하단 가상패드·마우스 추종 4모드 → 같은 `PlayerCommand`, UI·월드 입력 분리, 이동 테스트 씬 | 이동과 회피가 자연스러운가 | 마우스 중심 데드존 안 입력 0, 좌클릭 유지 시 누른 순간 1회만 대시, 모바일 터치는 기획서의 테스트 제안 |
| M3. 먹이·성장 | 타일별 랜덤 리젠·상한·몸체 점유 차단, 고정 표면 거리 흡수·선점·중단 위치 보존, 먹이 1개=1점·동일 외형/충돌 반경, 성장 연동 카메라 줌 | 수집·성장만으로 재미가 있는가 | 월드 1000×1000·타일 5×5는 초기 가정, n·리젠 주기·성장 곡선은 밸런스 데이터 |
| M4. 허기·플레이 흐름 | 포만 감소·소진 시 사망(몸집·점수 연소 없음), 결과 화면, 첫 화면 복귀 상태 전환 | — | 포만 소진 사망은 최신 기획으로 확정, 감소율은 임시값 |
| M5. 첫 화면 | 외형(원형 placeholder) 선택, 닉네임, 조작 4종 선택, PlayerPrefs 저장·복원 | — | 첫 실행 기본 조작: PC 마우스 추종·모바일 가상패드, 닉네임은 길이만 제한 |
| M6. 생태계 | 테스트 AI, 초식 사망 고기 드롭, 고기 섭취·변이, 크기 우위 육식의 접촉 처치 | 자석이 원치 않는 변이를 강제하지 않는가, 접촉 즉사에 대응 여지가 있는가, 순환이 실제로 일어나는가 | 접촉 예외 규칙이 많아 착수 전에 별도로 결정 |
| M7. HUD | 좌상단 랭킹, 머리 위 닉네임·포만 게이지, 우상단 설정 버튼, 모바일 대시 버튼 | 큰 개체의 시야 우위가 과도하지 않은가 | 랭킹 상위 10명, 대시 버튼 우하단 |
