## 설계 원칙

### 게임 규칙과 표현 분리

허기, 섭취, 질량, 변이, 사망 같은 규칙은 GameObject 표현과 가능한 한 분리합니다. 핵심 수치는 단위 테스트가 가능한 순수 C# 로직으로 유지하고 MonoBehaviour는 입력, Unity 생명주기, 표시 연결을 담당하도록 합니다.

### 입력 추상화

첫 화면의 WASD / 방향키 / 가상패드 / 터치/마우스 추종 네 선택지가 같은 이동 명령을 생성하게 합니다. 두 키보드 모드는 별도 선택지이고 가상패드는 좌하단 고정입니다. 포인터 목표를 방향으로 변환하는 계층과 실제 캐릭터 이동을 분리합니다.

```text
키보드·마우스 ─┐
                ├→ Input Actions → Player Command → Movement/Combat
가상 조이스틱 ──┘
```

게임플레이 시스템은 입력 장치가 아니라 이동 벡터와 행동 명령을 소비해야 합니다.

### 데이터 기반 밸런스

값·곡선은 [밸런스 데이터 목록](BALANCE_PARAMETERS.md)에서 관리합니다. 다음 수치는 코드 상수가 아니라 설정 데이터로 조정할 수 있어야 합니다.

- 허기 최대치와 감소율
- 먹이별 포만 회복량(점수는 모든 먹이 1개당 1점으로 고정)
- 몸집에 따른 외형 배율
- 변이 임계치와 효율
- 사망 시 생체 물질 환원율
- 이동 속도와 접촉 판정 우위 기준
- 몸 표면 기준 고정 흡수 여유 거리와 흡수 속도
- 월드·리젠 타일 크기, 타일별 상한과 리젠 주기
- 카메라 줌 곡선과 보간
- 가속·감속·방향 전환 응답과 크기별 속도 감소 곡선
- 대시 배율·지속시간·쿨타임

초기에는 ScriptableObject 사용을 고려하되 권위 서버(ASP.NET Core)와 밸런스 설정을 공유하는 방식은 아직 정하지 않았습니다.

### 온라인 경계

서버는 ASP.NET Core(.NET 10)로 만들고 클라이언트와 WebSocket으로 통신합니다. 근거는 [결정 기록](DECISIONS.md)에 있습니다.

- 게임 규칙과 프로토콜 정의는 `Shared/`에 둡니다. 서버가 같은 코드로 권위 판정을 하고 클라이언트는 예측과 로컬 테스트에 사용합니다.
- `Shared/`는 Unity와 서버 양쪽에서 컴파일되므로 netstandard2.1과 C# 9 범위만 사용하고, `UnityEngine`이나 ASP.NET Core를 참조하지 않습니다.
- 네트워크 송수신 코드는 `Shared/`의 도메인 로직에 섞지 않고 클라이언트·서버 각자의 Networking 계층에 둡니다.
- 서버 틱, 권위 범위, 보간·예측 방식은 아직 결정하지 않았습니다.

`Shared/Runtime/Protocol`의 `MessageCodec`이 `[MessageType 1바이트][내용]` 형식을 수동으로 인코딩합니다. 직렬화 라이브러리가 정해지면 교체할 **임시 구현**입니다. 현재 메시지는 연결 확인과 RTT 측정용 `Ping`/`Pong`뿐입니다.


### 이동 규칙과 입력 구조 — 로드맵 M1·M2

```text
Shared/Runtime/Movement/
  PlayerCommand.cs       장치 독립 명령: 이동 벡터(길이 0~1)와 이번 스텝의 대시 누름
  MovementSettings.cs    MOVE·DASH 밸런스 값(임시값, [Serializable] public 필드)
  MovementState.cs       위치·속도·마지막 유효 방향·대시 상태
  MovementSystem.cs      Step(ref state, command, size, settings, dt)
Client/Assets/MutatIO/Runtime/
  Input/PlayerCommandSource.cs  선택한 조작 모드의 장치 입력 → PlayerCommand
  Input/VirtualJoystick.cs      좌하단 고정 가상패드. 자신을 누른 포인터만 추적
  Input/DashButton.cs           화면 대시 버튼
  Input/PointerFollow.cs        화면상 캐릭터 → 포인터 방향 계산
  Input/UiPointerFilter.cs      화면 좌표가 UI 위인지 직접 레이캐스트로 판정

```

- 관성은 속도 벡터가 목표 속도로 일정 비율만큼 다가가는 방식입니다. 방향 전환도 같은 가속 응답을 쓰며 회전 반경 제한은 없습니다.
- 몸집은 초기 몸집을 1로 둔 상대값입니다. 속도 배율은 `몸집^(-지수)`이며 최소 배율로 하한을 둡니다. 곡선 형태 자체도 임시입니다.
- 대시 방향은 현재 이동 입력, 입력이 없으면 마지막 유효 방향입니다. 대기시간은 대시가 끝난 시점부터 줄어듭니다.
- 키보드는 Input System `InputAction`(2DVector 컴포지트)으로 읽습니다. 프로젝트 전역 액션 에셋(`Assets/Settings/InputSystem_Actions.inputactions`)은 아직 쓰지 않습니다.
- PC 마우스 추종은 매 프레임 화면상 캐릭터 위치와 커서로 방향을 다시 계산하므로 카메라가 움직여도 고정 목적지가 생기지 않습니다.
- 터치가 감지되면 터치 조작으로, 터치 후 0.5초가 지나 마우스가 움직이면 다시 마우스 조작으로 봅니다.

### 월드·먹이·성장·카메라 — 로드맵 M3

> 2026-10-17 M6 착수 전에 확정 기획(타일 리젠·생성 타일 귀속·흡수 선점과 중단·먹이 1개=1점·카메라 경계와 짧은 변 시야)에 맞춰 다시 구현했습니다.

```text
Shared/Runtime/
  World/WorldSimulation.cs   생명체 이동 → 맵 경계 → 먹이 흡수·섭취 → 성장을 Step(dt)으로 진행
  World/WorldSettings.cs     맵 크기와 이동·성장·먹이 설정 묶음
  World/WorldBounds.cs       원점 중심 사각 맵 경계, 원 단위 위치 제한
  Creatures/Creature.cs      ID, 이동 상태, 섭취 개수(점수, 정수), 몸집, 다음 스텝 명령
  Feeding/FoodField.cs       타일별 초식 리젠·점유 차단, 흡수 선점·해제, 끌어당김, 섭취 판정, 공간 분할 조회
  Growth/GrowthSystem.cs     점수 → 몸집
Client/Assets/MutatIO/Runtime/
  World/WorldSimulationRunner.cs  매 프레임 내 명령을 넣고 Time.deltaTime으로 Step
  Creatures/CreatureView.cs       생명체 상태 → Transform
  Feeding/FoodFieldView.cs        카메라에 보이는 먹이만 조회해 재사용 스프라이트로 표시
  Cameras/WorldCameraController.cs  내 생명체 추적, 몸집 연동 줌, 짧은 변 기준 시야, 월드 경계 제한
```

- 클라이언트 표시 컴포넌트는 시뮬레이션 상태를 읽기만 하고 규칙을 계산하지 않습니다. 서버로 옮길 때 `WorldSimulation`을 그대로 사용하는 것이 목표입니다.
- 초식 먹이는 한 변 `tileSize`(5) 타일마다 관리합니다. 타일 안 랜덤 위치에 생성하고 그 타일을 귀속 타일(`FoodItem.OriginTile`)로 기록합니다. 타일 상한은 귀속 타일이 생성해 아직 남은 개수로 세며, 다른 타일로 끌려가도 바뀌지 않고 섭취될 때만 줄어듭니다.
- 리젠 시점에 생명체 원이 조금이라도 덮은 타일은 모두 생성하지 않습니다(중심 소속 타일만 검사하지 않음). 이미 있는 먹이는 제거하지 않습니다.
- 흡수 반경은 몸 반경 + 고정 거리입니다. 먼저 반경에 들어온 생명체가 선점하고, 같은 스텝이면 생명체 목록 순서상 먼저 판정된 하나에 배정합니다. 선점은 대상이 월드에서 사라질 때(사망·이탈)만 풀리며 거리로 해제하지 않습니다. 변이로 인한 해제는 M6에서 연결합니다.
- 먹이 1개 = 1점입니다. 먹이별 점수 값은 없고 섭취 완료 시 점수 1을 한 번만 더합니다.
- 먹이는 섭취 시 목록에서 즉시 제거되므로 보상이 한 번만 지급됩니다. 랜덤 배치는 시드가 있는 `System.Random`을 사용합니다.
- 먹이 탐색은 리젠 타일과 같은 격자를 공간 분할로 써서 생명체 주변 칸만 검사합니다. 리젠은 매 스텝 전체 타일(1000×1000이면 4만 개)을 훑습니다. Editor에서 먹이 4만 개 기준 스텝당 약 0.12ms였습니다.
- 몸집은 섭취량에 따라 면적이 늘도록 `√(1 + 점수 × 계수)`입니다. 몸 원의 외형 지름과 충돌 지름은 같습니다.
- 카메라는 몸집별 범위(`기본값 × 몸집^지수`, 최소·최대 제한)를 화면의 짧은 변에 맞추고 긴 변은 비율만큼 더 보여줍니다. 보이는 영역을 월드 안으로 제한해 맵 끝에서 멈추며, 보이는 영역이 월드보다 큰 축은 월드 중심에 맞추고 월드 밖은 카메라 배경색으로 구분합니다. 줌·화면 비율 변화는 매 프레임 다시 계산합니다.

### 허기·플레이 흐름 — 로드맵 M4

```text
Shared/Runtime/
  Hunger/HungerSettings.cs   HUNGER·FOOD-05 밸런스 값(임시값)
  Hunger/HungerSystem.cs     포만 감소·회복, 먹이 종류별 기본 회복량 × 몸집별 회복 배율
  Creatures/CreatureDeath.cs 사망 정보(생명체, 원인)
Client/Assets/MutatIO/Runtime/
  Flow/GameFlow.cs           첫 화면 → 플레이 → 결과 → 첫 화면 상태 전환과 이번 생 결과
```

- `WorldSimulation.Step`은 이동 → 먹이 흡수·섭취(점수·포만 회복) → 포만 감소 → 사망 처리 순서입니다. 같은 스텝에 먹은 회복을 먼저 반영합니다.
- 시간당 포만 감소는 몸집·역할과 무관한 공통값입니다. 대신 먹이 하나의 회복량에 몸집별 배율 `max(하한, 몸집^-지수)`를 곱해 클수록 같은 먹이로 덜 회복합니다. 배율은 그 먹이를 먹기 전 몸집으로 계산합니다.
- 포만이 0이 되면 생명체를 월드에서 제거하고 `CreatureDied`를 발생시킵니다. 점수·몸집은 사망 시점 값을 유지합니다. 흡수 중이던 먹이는 다음 스텝에 대상이 없어 현재 위치에서 해제됩니다.
- 클라이언트 월드는 내 생명체가 없는 첫 화면·결과 화면에서도 계속 진행합니다. 사망하면 내 생명체 표시를 지우고 카메라는 사망 위치에 멈춥니다. 다시 입장하면 같은 월드에 새 생명체(점수 0, 입장 포만)를 만듭니다.
- `GameFlow`는 화면을 만들지 않는 순수 상태 클래스이며 허용되지 않은 전환은 무시합니다. 현재 화면 구성은 `PrototypeBootstrap`이 합니다.

```text
Client/Assets/MutatIO/Runtime/
  Profile/CharacterAppearances.cs  외형 ID 목록(저장용 안정 문자열 ID)과 기본값
```

- 첫 화면 한 곳에 외형 선택·닉네임 입력·조작 4종 선택·입장 버튼을 둡니다. 화면 구성은 `PrototypeBootstrap`이 합니다.
- 입장 버튼을 누를 때만 저장합니다. 첫 화면에 들어올 때마다(시작·결과 확인 후) 저장값을 불러와 표시합니다.

- 외형은 표시 전용입니다. 시뮬레이션 `Creature`에는 외형을 넣지 않았습니다. 같은 원형 몸체에 귀(몸 뒤)·얼굴(눈·표정, 몸 위)을 별도 스프라이트로 얹으며, 장식은 충돌 반경에 포함하지 않습니다.
- 몸과 귀의 색은 역할 표현용이고 외형은 장식 형태로만 구분합니다. 색은 임시 팔레트 기본안(초식 #4CC9F0, 초식 먹이 #67D66B, 육식 먹이 #FF6B6B, 월드 바탕 #17212B)을 쓰며 표시 쪽 값이라 교체할 수 있습니다. 윤곽색 #EDF4FF는 아직 쓰지 않습니다.
- 조작 선택 버튼은 첫 화면으로 옮겼고 플레이 중 조작 변경 버튼은 제거했습니다(플레이 중 변경 허용 여부는 미결정).

```text
Shared/Runtime/
  Bots/BotSettings.cs        BOT 밸런스 값(최소 인원·입장 지연·수준·수준 0/1 행동 값·입장 영역, 임시값)
  Bots/BotSkill.cs           수준(0~1) → 실제 행동 값 보간
  Bots/BotBrain.cs           봇 한 마리의 판단: 위험 회피 → (육식) 사냥감 추격 → 가까운 먹이 → 배회, PlayerCommand 생성
  Bots/BotDirector.cs        최소 인원 유지, 무작위 지연 입장, 사망 시 퇴장 처리, 모든 봇의 명령 갱신
  Bots/BotNames.cs           영문 이름 목록과 사용 중 이름을 피한 무작위 선택
  Bots/Bot.cs                이름·생명체·판단·수준 편차
  Creatures/CreatureRole.cs  초식·육식 역할(모두 초식으로 시작, 변이는 M6)
  Creatures/EcologyRules.cs  확정 규칙: 처치 가능 여부(육식이고 점수가 엄격히 높음), 역할별 먹을 수 있는 먹이
```

- 봇은 사람과 같은 `Creature`이며 `PlayerCommand`만 만들어 넣습니다. 시뮬레이션에 봇 전용 규칙은 없습니다. 순수 C#이므로 온라인 단계에서 서버가 같은 `BotDirector`를 실행하는 것이 목표입니다.
- 인원 = `ConnectedHumans`(접속한 사람, 생존 여부와 무관) + 봇 수입니다. 로컬 프로토타입은 나를 접속한 사람 1명으로 고정해 첫 화면·결과 화면에서도 봇 4명을 유지합니다.
- `WorldSimulationRunner`는 매 프레임 내 명령 → `BotDirector.Update(dt)`(입장 대기·봇 명령) → `WorldSimulation.Step(dt)` 순서로 진행합니다. 월드 시작 시(`Start`)에는 지연 없이 빈자리를 채웁니다.
- 판단은 수준별 주기마다 하고, 그 사이에는 정한 목표(먹이·사냥감 위치)를 따라 방향만 갱신합니다. 위험은 한 번 알아차리면 인지 범위를 벗어날 때까지 기억해 도주가 끊기지 않게 합니다. 다른 개체가 선점한 먹이는 노리지 않습니다.
- 수준을 바꾸면 이미 입장한 봇에도 즉시 적용합니다. 수준이 낮으면 판단이 늦고, 인지 범위가 좁고, 위험을 놓치고, 먹이를 덜 노리고, 조준이 부정확하고, 느리게 움직여 결국 굶어 죽습니다.
- 표시는 `PrototypeBootstrap`이 `BotJoined`·`BotLeft`로 봇 생명체 오브젝트를 만들고 지웁니다. `CreatureView.SetRoleColors`로 역할에 따라 몸·귀 색(초식 #4CC9F0, 육식 #B56EFF)을 바꿉니다.

### 생태계 — 로드맵 M6

```text
Shared/Runtime/
  Mutation/MutationSettings.cs  MUTATE 밸런스 값(임시값)
  Mutation/MutationSystem.cs    몸집별 변이 임계치, 시간 감소
  Combat/ContactSettings.cs     PUSH 밸런스 값(임시값)
  Combat/ContactSystem.cs       초식끼리 밀침, 접촉 처치 판정(일괄)
  Creatures/CreatureDeath.cs    사망 원인(굶주림·처치)과 처치자
Client/Assets/MutatIO/Runtime/
  Creatures/CreatureView.cs     역할색, 변이 게이지, 고기 섭취 피드백
```

- `WorldSimulation.Step` 순서: 이동·경계 → 초식 밀침 → 육식의 초식 먹이 밀기 → 먹이 흡수·섭취(점수·몸집·포만·변이, 임계치 도달 시 육식 전환) → 갱신된 상태로 접촉 처치 판정 → 포만·변이 감소와 굶주림 판정 → 사망 일괄 반영(초식은 고기를 남김).
- 흡수는 `EcologyRules.CanEat`으로 역할별 먹을 수 있는 먹이만 선점합니다. 육식은 초식 먹이를 끌어당기지 않고 몸에 닿으면 밀어냅니다. 밀린 먹이의 귀속 타일은 바뀌지 않습니다.
- 역할 변경은 `WorldSimulation.ChangeRole`로만 합니다. 변이 수치를 0으로 두고 진행 중인 흡수를 현재 위치에 남긴 채 해제하며 `CreatureMutated`를 발생시킵니다.
- 처치 조건은 `EcologyRules.CanKill`(육식이고 점수가 엄격히 높음)이며 대시 중에도 같습니다. 접촉은 몸 원이 겹친 경우(중심 거리 < 반경 합)입니다.
- 고기는 타일 리젠과 무관한 먹이로 생성하며 타일 상한에 포함하지 않습니다.
- 클라이언트는 `FoodConsumed`에서 초식이 고기를 먹으면 피드백을 재생하고, 변이 게이지는 매 프레임 `Mutation / 임계치`로 그립니다.

## 탑다운 표현과 프로토타입 팔레트

- 게임은 탑다운 2D로 고정합니다. 거리·크기·점유는 같은 2D 월드 평면에서 해석합니다.
- 원근 왜곡 없는 표시를 유지합니다. 카메라 범위 변경으로 시야를 조절합니다.
- 귀·눈·표정 등 장식은 몸체 원과 분리하며 장식 때문에 충돌 반경을 바꾸지 않습니다.
- 역할 상태 색과 캐릭터별 장식 선택을 분리합니다. 아트 확정 전 팔레트는 GAME_DESIGN의 HEX 기본안을 참조합니다.
- 색상은 표시 설정으로 교체할 수 있게 하고 게임 규칙에서 RGB 값으로 역할을 판정하지 않습니다.
- 카메라 가시 영역은 월드 안으로 제한합니다. 가시 영역이 월드보다 큰 축은 중심 정렬하고 바깥 배경을 표시합니다.
- 몸집에서 구한 기본 가시 범위를 화면의 짧은 변에 적용합니다. 화면 비율 a=가로/세로, 짧은 변의 전체 월드 범위 D라면 가시 폭은 D×max(1,a), 높이는 D×max(1,1/a)입니다.
- 줌·화면 비율이 바뀌면 가시 폭·높이를 갱신한 뒤 월드 경계 제한을 축별 다시 계산합니다. 원형 표시와 충돌 반경에 비균일 스케일을 적용하지 않습니다.
- 위 정책은 구현 목표입니다. 현재 카메라가 이미 충족하는지 검증하지 않았으므로 구현 완료로 표시하지 않습니다.

## 이번 기획의 구현 경계

- 첫 화면, 월드 플레이, 사망 결과를 명확한 상태로 구분합니다. 사망 후 자동 재스폰하지 않습니다.
- 캐릭터 외형과 초식/육식 상태를 분리하고 색상은 상태 표현에 사용합니다.
- 자석 흡수 연출과 단일 보상 처리를 분리합니다. 온라인 판정 권한은 별도 결정합니다.
- 사망 드롭은 초식에만 적용합니다. 육식 사망 이벤트에 공통 드롭을 연결하지 않습니다.
- 포만 게이지와 닉네임은 캐릭터 추적 표시이며, 랭킹·설정은 화면 고정 UI입니다.
- 월드 크기와 충돌 판정값을 UI 픽셀 크기나 줌 배율로 산정하지 않습니다.
- 접촉 판정의 미정 조건을 임의로 확정하지 않습니다.
- 대시와 이동은 같은 장치 독립 명령 체계를 사용합니다.

## 먹이·성장 판정 경계

- 먹이 1개 섭취 완료 시 점수 1점을 한 번만 지급합니다. 독립 현재 질량 자원을 두지 않습니다.
- 몸집은 점수에서 계산한 반경이며 표시 원과 충돌 원에 같은 값을 사용합니다. 화면 픽셀이나 카메라 줌에서 반경을 역산하지 않습니다.
- 굶주림은 점수·몸집 연소가 아니라 포만 소진 시 사망입니다.
- 초식 리젠은 타일별로 상한과 주기를 관리합니다. 초기 가정은 월드 1000×1000, 타일 5×5이며 내부 랜덤 위치를 사용합니다.
- 점유 판정은 캐릭터 중심의 소속 타일만 검사하지 않습니다. 캐릭터 원과 겹치는 모든 타일에서 초식 리젠을 차단합니다.
- 타일 점유와 초식 먹이 개수 상한은 서로 독립된 생성 조건입니다. 어느 한 조건이 막히면 생성하지 않습니다.
- 중심 기준 흡수 거리 = 몸 반경 + 고정 흡수 여유 거리입니다. 몸 반경에 추가 흡수 배율을 곱하지 않습니다.
- 처리상 먼저 근접한 유효 대상에게 먹이를 선점시킵니다. 아직 어떤 스레드/서버 틱 모델로 처리할지 확정한 것은 아닙니다.
- 사망·이탈·변이로 흡수를 취소하면 현재 위치를 유지하고 선점을 해제합니다. 섭취 완료 전 보상을 지급하지 않습니다.
- 초식 먹이는 생성 타일 식별자를 유지합니다. 위치가 바뀌어도 타일별 잔존 개수는 생성 타일 기준으로 계산하고, 섭취·제거 시 그 타일에서 차감합니다.
- 육식은 초식 먹이 흡수 후보에서 제외합니다. 몸체 접촉으로 밀되 먹이를 제거하거나 보상을 지급하지 않습니다.
- 시간당 공통 허기 감소율 하나를 사용하고 몸집·역할별 감소 배율을 적용하지 않습니다.
- 먹이 한 개의 포만 회복량에는 몸집별 감소 곡선을 적용합니다(HUNGER-05). 감소율과 섭취 회복량을 혼동하지 않습니다.
- 변이 임계치는 기본값과 몸집별 증가 곡선(MUTATE-04)을 결합합니다. 누적 수치를 임계치 재계산만으로 초기화하지 않습니다.
- 초식 변이 수치는 고기 섭취 때 증가하고 시간에 따라 감소하여 0에서 멈춥니다. 포만·점수와 분리하며 0에서 게이지를 숨깁니다.
- 변이 피드백은 개별 고기 섭취 완료에 연결합니다. 구체적인 캐릭터·화면 연출은 미결정입니다.
- 동일 크기 및 작은 육식/큰 초식은 처치하지 않고, 초식끼리는 밀칩니다. 대시도 같은 접촉 처치 기준을 사용합니다.
- 섭취 완료·점수·성장·변이를 접촉 처치보다 먼저 반영합니다. 처리 우위는 점수의 엄격한 대소 비교로 판단하고 별도의 최소 차이는 쓰지 않습니다.
- 여러 접촉의 사망 일괄 반영과 포만 소진·변이 자연 감소의 세부 우선순위는 아직 미결정입니다. 컬렉션 순회 순서로 임의 고정하지 않습니다.
- 성장·먹이 규칙은 Shared의 순수 C# 로직과 서버 판정 경계에 맞춰 구현하되 이번 문서 변경으로 구현 완료를 표시하지 않습니다.

## 이동과 설정 저장

- 별도의 선회 속도 제한 없이 약한 관성을 속도 벡터 응답으로 표현합니다.
- 크기가 커질수록 이동속도를 완만하게 감소시킵니다. 곡선과 하한은 테스트 데이터입니다.
- 대시는 현재 유효 이동 방향, 정지 시 마지막 유효 이동 방향을 사용합니다. 첫 이동 전 처리와 정지 판정 임계값은 구현 전에 정합니다.
- UI 입력은 월드 이동에 사용하지 않습니다. 이동 터치와 대시 버튼 터치를 구분하며 UI 클릭을 월드 대시에 중복 사용하지 않습니다.
- PC 마우스는 버튼을 누르지 않아도 커서를 추종합니다. 좌클릭은 대시 입력이며 해제해도 추종은 유지됩니다. 고정 클릭 월드 좌표를 목적지로 사용하지 않습니다.
- 모바일 터치 해제·중심 데드존·카메라 이동 시 좌표 갱신과 UI 위에서의 기존 이동 처리는 INPUT_REFERENCE.md의 미확인 사항을 임의로 확정하지 않습니다.
- 캐릭터 식별자, 닉네임, 조작 모드를 PlayerPrefs에 저장하고 첫 화면 복귀·재실행 시 복원합니다.
- 설정 확정 시 저장하고 매 프레임 저장하지 않습니다. 저장값이 없거나 삭제된 캐릭터 등 유효하지 않은 값이면 기본값으로 복구합니다.
- Web의 PlayerPrefs는 브라우저 IndexedDB에 저장됩니다. 브라우저 데이터 삭제 시 복원이 불가능할 수 있으므로 기본값 처리를 둡니다.
- 저장 대상에 현재 점수·몸집·육식 상태·월드 접속 상태를 포함하지 않습니다.

참고: [Unity PlayerPrefs 공식 문서](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/PlayerPrefs.html)

## WebGL 고려사항

- 브라우저에서 지원되지 않거나 제약이 큰 API를 도입하기 전에 확인합니다.
- 메인 스레드 비용, GC 할당, 다운로드 크기와 메모리를 관리합니다.
- 터치 입력과 가변 해상도를 막지 않는 UI를 사용합니다.
- 브라우저 제약으로 WebSocket을 사용하며, WebGL에서는 jslib 브리지(`WebGLWebSocketTransport`)로 브라우저 WebSocket을 호출합니다. 서버 배포·호스팅 구조는 아직 정하지 않았습니다.
- 기능 완료 판정에는 필요할 경우 실제 WebGL 빌드 검증을 포함합니다.

## Unity CLI와 Pipeline

Unity Pipeline은 실행 중인 Unity Editor에 로컬 HTTP API로 연결하여 CLI나 에이전트가 명령을 실행하게 합니다.

```bash
unity command --project-path "$(pwd)/Client"
unity command --project-path "$(pwd)/Client" editor_status
unity command --project-path "$(pwd)/Client" console_status
unity command --project-path "$(pwd)/Client" console --level error --tail 20
```

첫 번째 명령으로 현재 버전에서 제공되는 명령 목록을 확인한 뒤 사용합니다. 씬과 에셋을 자동 수정하는 경우 명령 수행 후 콘솔 오류와 실제 씬 상태를 다시 확인합니다.

공식 문서: https://docs.unity3d.com/Packages/com.unity.pipeline@0.8/manual/connectivity.html
