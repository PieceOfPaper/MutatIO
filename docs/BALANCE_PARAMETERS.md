# 밸런스 데이터 목록

- 상태: 초기 가정과 플레이 테스트용 데이터 목록
- 마지막 갱신: 2026-10-17

[게임 기획서](GAME_DESIGN.md)는 규칙, 이 문서는 조정 가능한 값·곡선, [미결정 항목](OPEN_DESIGN_QUESTIONS.md)은 아직 선택하지 않은 규칙을 관리합니다.

## 사용 규칙

- 아래 초기 가정과 '코드 연결과 현재 임시값'에 기록한 값 외의 조정값은 **미설정**입니다. 초기 가정과 구현 임시값은 최종 밸런스 확정과 구분합니다.
- 구현에 수치가 필요하면 임시값임을 표시하고 설정 데이터로 노출합니다.
- 규칙 자체를 바꾸는 선택은 결정 기록에 남기고, 수치 조정은 아래 실험 기록으로 관리합니다.
- 코드 설정의 실제 필드와 이 목록을 연결해 같은 값의 정의가 여러 곳에 생기지 않게 합니다.
- 단위, 유효 범위, 임시값, 테스트 결과, 채택 이유를 함께 기록합니다.
- 조작 방식끼리 기본 성능 차이가 나지 않는지 동일 조건으로 비교합니다.

## 0. 초기 가정과 고정 규칙

| 항목 ID | 항목 | 초기 가정/상태 | 설명 |
| --- | --- | --- | --- |
| WORLD-01 | 월드 크기 | 1000×1000 월드 단위, 초기 가정 | 최종 크기는 테스트 후 조정 |
| FOOD-01 | 초식 리젠 타일 크기 | 5×5 월드 단위, 초기 가정 | 타일 안에서 랜덤 생성 |
| FOOD-03 | 타일별 초식 먹이 상한 n | 미설정, 양의 정수 | 먹이를 한 번에 n개 모두 채운다는 뜻은 아님 |
| SERVER-01 | 목표 월드 동시 접속자 수 | 미설정, 명 | 부하·밀도 검증 목표 |
| SERVER-02 | 서버 틱/스냅샷 주기 | 미설정, Hz/초 | 서버 판정·동기화 설계 후 측정 |
| UI-01 | 닉네임 길이 제한 | 미설정, 문자 수 기준 | 문자 계산 정책과 함께 결정 |

고정 규칙은 아래와 같으며 일반적인 수치 튜닝으로 바꾸지 않습니다.
- 먹이 1개 = 1점. 먹이별 점수 가중치는 없습니다(기존 FOOD-04 항목 폐기).
- 점수와 독립된 현재 질량 자원을 두지 않습니다.
- 시간당 허기 감소에는 몸집·역할 배율을 사용하지 않습니다(기존 HUNGER-03 폐기). 먹이당 포만 회복량에는 별도 몸집 배율(HUNGER-05)을 적용합니다.
- 처치 크기 우위는 점수를 엄격히 비교하며 최소 차이·비율은 사용하지 않습니다(기존 CONTACT-02 폐기).
- 섭취·점수·성장·변이를 먼저 반영한 뒤 접촉을 판정합니다.
- 변이 수치가 0이면 게이지를 숨깁니다. 감소 때문에 점수·몸집이 줄지 않습니다.
- 초식 먹이의 귀속 타일은 생성 후 이동해도 바뀌지 않습니다.
- 대시 중 접촉 처치 규칙은 일반 이동과 같습니다.
- 원형 외형 반경 = 충돌 반경. 별도 접촉 반경 배율을 두지 않습니다(기존 CONTACT-01 폐기).
- 굶주림으로 점수·몸집을 감소시키지 않고 포만 소진 시 사망합니다(기존 HUNGER-04 폐기).
- 흡수 시작 거리는 몸 반경 + 고정 표면 여유 거리입니다. 몸집 비례 추가 배율은 없습니다(기존 MAGNET-04 폐기).
- 현재 가정의 타일 수는 40,000, 초식 먹이 이론 상한은 40,000×n개입니다.

### 크기별 생존·변이 데이터 관계

- 포만 회복 = FOOD-05의 먹이·역할별 기본 회복량 × HUNGER-05의 몸집 배율.
- 시간당 포만 감소는 HUNGER-02 공통값을 유지합니다. 역할별 고기 회복 효율 FOOD-06은 기존 정의에 따라 적용하며 중복 곱하지 않습니다.
- 변이 임계치 = MUTATE-01 × MUTATE-04의 몸집 배율.
- 고기 1개의 변이 증가량은 MUTATE-03, 시간당 감소는 MUTATE-02입니다.
- 시간 감소가 없다고 가정할 때 필요한 고기 개수는 대략 올림(임계치 / 고기당 증가량)입니다. 실제로는 섭취 속도와 자연 감소, 성장으로 바뀌는 임계치까지 테스트합니다.
- 크기별 두 곡선은 독립적으로 조정합니다. 포만 효율 감소가 자동으로 고기당 변이 증가량까지 감소시키는 구조를 넣지 않습니다.
- 구체적인 곡선·배율은 아직 미설정이며 코드의 현재 임시 수치를 덮어쓰지 않습니다.
