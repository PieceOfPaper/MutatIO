## 이번에 구체화된 내용

캐릭터 선택과 닉네임 입력, 두 이동 방식, HUD 위치, 머리 위 닉네임·포만 게이지, 자석형 먹이 흡수, 먹이 색상, 초식 사망 전용 드롭, 몸집 기반 접촉 처치, 성장 연동 카메라, 대시, 사망 결과와 첫 화면 복귀를 구체화했습니다. 세부 수치는 아래 질문으로 남깁니다.

## P0 — 화면과 조작

- 조작 선택을 첫 화면의 캐릭터·닉네임 입력 옆에 둘 것인가? 현재는 같은 화면에 두는 제안입니다.
- 키보드 이동 키는 무엇인가? WASD와 방향키를 모두 지원하는가?
- 포인터 방식은 누르는 동안 목표 방향으로 이동하는가, 한 번 찍은 위치까지 자동 이동하는가?
- 포인터가 캐릭터 중심에 가까워지거나 손을 떼면 멈추는가?
- 포인터를 화면에 고정했을 때 카메라 이동에 따라 목표를 갱신하는가?
- 가상 조이스틱은 고정형인가, 터치 위치에서 생성되는가?
- 이동의 관성, 회전, 가속과 몸집별 속도 차이가 있는가?
- 대시 방향은 현재 이동 방향인가, 마지막 방향인가? 정지 중에도 가능한가?
- 대시 배율, 지속시간, 쿨타임, 사용 비용은 얼마인가?
- PC 포인터 조작에서 스페이스 이외의 대시 입력이 필요한가?
- UI 클릭과 월드 이동 입력, 이동 터치와 대시 터치를 어떻게 분리하는가?
- 캐릭터·닉네임·조작 설정은 재입장 또는 브라우저 재실행 시 유지하는가?

## P0 — 성장과 먹이

- 먹은 양의 단위와 먹이별 점수·허기 회복량은 얼마인가?
- 누적 점수와 현재 질량을 분리할 것인가? 굶으면 점수 또는 몸집이 줄어드는가?
- 점수에서 시각 크기와 충돌 반경을 계산하는 공식은 무엇인가?
- 초식 먹이의 공간 간격과 리젠 주기는 얼마인가? 격자·영역·랜덤 중 무엇인가?
- 초식 먹이 최대 개수, 점유 위치 재생성, 서버 인원별 공급 조정이 필요한가?
- 자석 흡수 반경·속도·최종 섭취 거리는 얼마인가? 몸집에 비례하는가?
- 여러 개체가 같은 먹이에 접근했을 때 누가 흡수하는가?
- 흡수 도중 캐릭터가 사망·이탈하거나 변이하면 먹이는 어떻게 처리하는가?
- 초식 사망 시 누적 섭취량의 몇 퍼센트를 고기로 환원하는가?
- 고기의 조각 수, 조각별 영양량, 흩어짐 범위, 소멸 시간은 얼마인가?

## P0 — 허기·변이·접촉 판정

- 허기 감소율은 얼마이며 몸집에 따라 증가하는가?
- 포만 게이지 0에서 즉사, 체력 감소, 질량 소모 중 무엇을 적용하는가?
- 초식의 고기 허기 회복 효율은 육식 대비 정확히 50%인가?
- 육식 변이에 필요한 고기 누적량은 얼마인가? 시간에 따라 줄어드는가?
- 육식 전환 시 몸집을 보존하는가? 전환 시점과 예고는 어떻게 표시하는가?
- 육식은 초식 먹이를 먹을 수 있는가? 먹는다면 점수와 허기는 어떻게 처리하는가?
- 같은 몸집끼리 육식이 포함된 접촉을 하면 어떻게 되는가?
- 작은 육식과 큰 초식이 닿았을 때 육식은 죽는가, 양쪽 모두 살아남는가?
- '더 크다'의 판정값과 최소 우위 차이 또는 비율은 무엇인가?
- 원형 충돌 반경과 시각적 외형의 관계는 무엇인가?
- 초식끼리 접촉 시 통과하는가, 서로 밀리는가?
- 여러 개체가 동시에 접촉하거나 같은 순간 성장·변이하면 어떤 순서로 처리하는가?
- 대시 중에도 동일한 접촉 판정을 사용하는가?
- 스폰 위치와 보호 시간을 어떻게 정하는가?

육식 사망 시 고기를 생성하지 않는 규칙은 확정했습니다. 변경하려면 별도 결정을 기록합니다.

## P0 — 카메라와 캐릭터 표현

- 정확한 시점은 탑다운 2D인가? 원형 표현만으로 시점까지 확정하지 않습니다.
- 카메라 범위와 몸집의 관계, 최대 줌아웃, 줌 보간 속도는 얼마인가?
- 맵 경계와 화면 비율별 최소 가시 영역은 어떻게 처리하는가?
- 원형을 유지하면서 캐릭터별 형태 차이를 어떻게 표현하는가?
- 초식·육식 캐릭터 색상은 무엇인가? 먹이의 초록·빨강과 어떻게 구분하는가?

## P0 — 온라인 구조

- 목표 동시 접속자 수, 월드 크기, 월드 인스턴스 구조
- 맵 경계, 플레이어 수에 따른 맵 확장 여부
- 클라이언트 이탈 시 개체의 존속·사망·드롭 처리
- 서버 권한 범위, 네트워크 솔루션, WebGL 전송 방식
- 서버 틱, 보간·예측, 지연 중 충돌 처리
- 서버·클라이언트 배포와 호스팅
- 먹이 중복 획득, 점수 조작과 반복 파밍 대응

## P1 — UI와 결과

- 닉네임 길이, 허용 문자, 중복 허용, 게스트 식별 방식
- 랭킹 표시 인원, 정렬 기준, 동점 순서, 갱신 주기와 내 순위 표시
- 설정 버튼 목록과 각 메뉴의 동작
- 머리 위 게이지 겹침, 화면 밖 표시와 큰 카메라 범위에서의 가독성
- 대시 버튼 위치와 쿨타임 표시
- 변이 진행도 표시
- 결과의 필수 획득 점수 외 생존 시간·최고 순위·처치 수 등의 추가 통계
- 결과 확인 전 연결 유지·관전 여부와 결과 영구 저장 여부
- 브라우저 탭 비활성화, 연결 복구, 화면 회전과 지원 브라우저 범위

## P2 — 확장

- 최종 외계 생명체·미생물 등 세계관과 아트
- 희귀 먹이, 위험 지역, 진화 분기
- 계정, 전적 저장, 업적, 시즌
- 수익화, 스킨, 친구, 파티, 비공개 방
- 사운드, 접근성 옵션

## 우선 검증할 가설

1. 초식의 먹이 수집과 성장만으로 재미가 유지되는가?
2. 포인터·방향 입력 모두 이동과 회피가 자연스러운가?
3. 먹이 자석이 원치 않는 고기 섭취와 변이를 강제하지 않는가?
4. 크기 우위의 접촉 즉사가 작은 캐릭터에게 대응할 여지를 주는가?
5. 큰 캐릭터의 넓은 시야가 대시·먹이 흡수 범위와 결합해 과도한 우위를 만들지 않는가?
6. 육식 사망 시 먹이가 사라지는 규칙이 포식자의 급격한 소멸을 유발하지 않는가?
7. 초식 과밀 → 굶주림 → 고기 → 변이가 실제로 발생하는가?
