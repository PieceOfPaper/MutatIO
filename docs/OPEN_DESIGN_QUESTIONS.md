## P0 — 첫 플레이 가능한 프로토타입 전에 결정

### 공간과 카메라

- 탑다운 2D, 대각 시점, 횡스크롤 중 어떤 시점을 사용할 것인가?
- 맵은 고정 크기인가, 플레이어 수에 따라 확장되는가?
- 경계는 벽, 순환, 위험 지대 중 무엇인가?
- 큰 개체를 카메라가 어떻게 따라가며 어느 범위까지 보여주는가?

### 이동과 입력

- 키보드는 WASD 이동인가, 마우스 지점 이동인가?
- 마우스는 방향 지정, 공격, 이동 중 어떤 역할을 맡는가?
- 가상 조이스틱은 고정형인가, 터치 위치 생성형인가?
- 공격은 별도 버튼인가, 접촉 판정인가, 자동 공격인가?
- 이동속도는 몸집과 상태에 따라 어떻게 변하는가?

### 먹이와 허기

- 기본 먹이는 어떤 규칙으로 어디에 생성되는가?
- 서버 인원에 따라 생성량을 고정할지 조정할지?
- 허기 0에서 즉사하는가, 체력 또는 질량을 먼저 소모하는가?
- 기본 먹이와 생체 물질의 허기·점수 효율은 각각 얼마인가?
- 큰 몸집이 허기를 더 빠르게 소모하는가?

### 성장과 사망

- 점수, 현재 질량, 누적 섭취량을 하나의 값으로 사용할 것인가?
- 점수 대비 외형 크기 곡선은 어떤 형태인가?
- 사망 시 질량의 몇 퍼센트가 생체 물질로 전환되는가?
- 생체 물질은 몇 조각으로 나뉘고 얼마 동안 유지되는가?
- 부활 위치와 보호 시간은 어떻게 결정하는가?

### 변이와 전투

- 생체 물질을 얼마나 먹어야 포식자가 되는가?
- 변이 수치는 시간이 지나면 감소하는가?
- 변이 시 기존 질량을 유지하는가, 일부를 비용으로 소모하는가?
- 포식자가 기본 먹이를 전혀 먹지 못하는가?
- 포식자끼리 공격과 섭취가 모두 가능한가?
- 공격, 체력, 피해, 처치 판정은 어떻게 구성하는가?
- 크기 차이가 전투 결과에 얼마나 영향을 주는가?

## P0 — 온라인 구조를 만들기 전에 결정

- 목표 동시 접속자 수는 몇 명인가?
- 한 서버가 하나의 영구 공간인가, 여러 인스턴스인가?
- 클라이언트 이탈 후 개체는 즉시 사라지는가?
- 서버 권위형 시뮬레이션을 어느 수준까지 적용하는가?
- ~~사용할 Unity 네트워크 솔루션과 백엔드는 무엇인가?~~ → 해결: ASP.NET Core 자체 서버 ([결정 기록](DECISIONS.md) 2026-10-17 — 서버 기술 스택)
- 서버 틱과 클라이언트 보간 목표는 얼마인가?
- ~~WebGL 클라이언트가 사용할 전송 방식은 무엇인가?~~ → 해결: WebSocket ([결정 기록](DECISIONS.md) 2026-10-17 — 서버 기술 스택)
- 배포 및 서버 호스팅 환경은 무엇인가?
- 부정행위 방지와 점수 검증을 어디서 수행하는가?

서버 기술 스택은 확정했습니다. 남은 질문은 서버 내부 구조(틱, 권위 범위, 방 구조)를 만들기 전에 정리합니다.

## P1 — 온라인 수직 슬라이스 전에 결정

- 닉네임과 게스트 식별 방식
- 리더보드 기준: 현재 점수, 생존 중 최고점, 누적점수
- 접속 직후 안전 구역과 스폰킬 방지
- 같은 플레이어 반복 처치와 협력 파밍 방지
- 지연 중 충돌·공격 판정
- 브라우저 탭 비활성화와 연결 복구
- 모바일 브라우저 성능 및 화면 회전 정책
- HUD에 표시할 허기, 점수, 변이, 순위 정보

## P2 — 핵심 재미 검증 이후 결정

- 외계 미생물, 세포, 포자, 슬라임 중 최종 아트 콘셉트
- 성장 단계별 외형 변화와 스킨
- 희귀 먹이와 위험 지역
- 포식자 종류 또는 진화 분기
- 계정, 전적, 업적, 시즌
- 수익화와 광고
- 친구, 파티, 비공개 방
- 사운드와 음악 방향
- 접근성 옵션

1. 먹기와 몸집 증가만으로 기본 생명체 플레이가 재미있는가?
2. 먹이 부족이 실제로 이동과 경쟁을 만들어내는가?
3. 생체 물질을 먹고 포식자로 변하는 선택이 명확하고 매력적인가?
4. 포식자가 너무 쉽게 생태계를 장악하거나 너무 빨리 굶지는 않는가?
5. 큰 개체의 죽음이 흥미로운 쟁탈전을 만드는가?
6. 키보드·마우스와 가상 조이스틱이 같은 규칙에서 모두 자연스러운가?
