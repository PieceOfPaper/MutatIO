# 미결정 기획 항목

- 문서 상태: 아직 정하지 않은 규칙만 관리
- 마지막 갱신: 2026-10-17

확정 규칙은 [게임 기획서](GAME_DESIGN.md), 조정할 수치·상한·주기·곡선은 [밸런스 데이터 목록](BALANCE_PARAMETERS.md)에 둡니다. 밸런스 데이터에 속하는 값은 이 문서에 중복 질문으로 남기지 않습니다.

## P0 — 화면과 조작

- 모바일 터치 해제와 캐릭터 중심 접근 시 정지 입력을 줄지, 마지막 방향을 유지할지?
- PC 마우스가 캐릭터 중심에 있을 때 어떤 동작을 할지?
- 좌클릭 유지 시 대시는 최초 한 번만 사용할지, 쿨타임마다 반복할지?
- 카메라 이동·줌 변화 시 마우스 추종 방향을 어떤 좌표 기준으로 갱신할지?
- 대시 중 방향 전환을 허용할지? 입장 후 첫 이동 전 대시 방향은 무엇인지?
- 대시 비용을 사용하는가? 사용한다면 어떤 자원인가?
- 첫 실행의 기본 조작과 기기에서 사용할 수 없는 선택지를 어떻게 표시하는가?
- 플레이 도중 설정에서 조작 변경을 허용하는가?
- 커서가 UI 위에 있을 때 기존 이동 방향을 유지할지, 감속할지?
- 설정 창을 열면 기존 이동을 멈추는가? 온라인 월드 진행은 어떻게 다루는가?

PC 마우스 추종과 UI 입력 분리는 이미 확정됐습니다. [레퍼런스 조사](INPUT_REFERENCE.md)는 확인 근거로만 참고합니다.

## P0 — 먹이 생성과 드롭

- 점유·상한 때문에 생성하지 못한 타일의 리젠 시계는 계속 주기대로 진행하는가, 빈 상태가 된 시점부터 다시 시작하는가?
- 초식 사망 드롭을 어떤 분배 방식으로 조각 수로 변환하는가? 반올림·잔여분 처리 방식은 무엇인가?

점수 단위, 점수·질량 분리, 타일 내 랜덤 배치, 몸체 점유 시 생성 금지, 표면에서 고정 거리 흡수, 먼저 근접한 대상 선점, 흡수 취소 위치는 확정됐으므로 질문에서 제외했습니다.

## P0 — 변이·접촉·스폰

- 변이 게이지를 어느 위치에 표시하고 다른 플레이어에게도 공개하는가?
- 고기 섭취마다 캐릭터 이펙트·화면 효과 중 어떤 연출을 쓰는가? 화면 효과를 누구에게 보여주는가?
- 육식 전환 완료 시 게이지를 어떻게 처리하고 어떤 완료 연출을 쓰는가?
- 섭취·성장·변이를 접촉보다 먼저 처리하는 것은 확정. 포만 소진·변이 자연 감소와 이 과정 사이 우선순위는?
- 여러 개체의 동시 접촉 사망을 한 번에 계산·반영할지, 순서대로 처리할지?
- 처치 없이 살아남은 육식 포함 접촉은 서로 밀리는가, 통과하는가?
- 여러 개체가 동시에 초식 먹이를 미는 경우의 처리 방식과 월드 경계에서 밀린 먹이 처리
- 입장 위치의 안전성 기준과 보호 기능 사용 여부

확정된 내용:
- 몸집·역할에 관계없이 시간당 허기 감소율은 동일하되, 클수록 먹이 한 개의 포만 회복량이 감소합니다.
- 클수록 변이에 필요한 고기 개수가 증가하도록 몸집별 임계치를 조절합니다.
- 처치 가능한 역할 조합에서 점수가 조금이라도 높으면 우위이며, 섭취와 성장을 접촉보다 먼저 처리합니다.
- 초식의 변이 수치는 시간에 따라 감소하며 0일 때 게이지를 숨깁니다.
- 육식은 초식 먹이를 먹지 못하고 밀어냅니다. 이동한 먹이는 최초 생성 타일의 개수로 셉니다.
- 작은 육식과 큰 초식은 둘 다 생존합니다. 동일 크기 접촉은 처치하지 않습니다.
- 초식끼리는 밀리며 대시에도 같은 접촉 처치 규칙을 사용합니다.

점수의 엄격한 대소 비교와 섭취 우선 처리는 확정됐습니다. 변이 임계치와 몸집별 배율·포만 회복 배율·연출 강도 등은 밸런스 데이터 문서에서만 관리합니다.

## P0 — 카메라와 캐릭터 표현

- 정식 아트 팔레트와 최종 캐릭터 장식 종류는 무엇인가? 프로토타입은 기획서의 청록 초식·보라 육식 기본안을 사용합니다.

탑다운 2D와 원형 몸체에 귀·눈 등 장식 차이를 주는 방식은 확정됐습니다. 카메라는 월드 경계에서 멈추고 화면의 짧은 변 기준으로 시야를 확보하는 것으로 확정됐습니다. 월드보다 큰 가시 영역은 해당 축 중심 정렬과 바깥 배경 표시를 사용합니다.

## P0 — 온라인 구조

- 월드 인스턴스와 방 입장 구조
- 월드 경계 동작과 동시 접속자 수에 따른 월드 확장 여부
- 이탈 시 개체의 존속·사망·드롭 처리
- 서버 권한 범위와 먹이 선점·섭취 완료 확정 주체
- 보간·예측 방식과 지연 중 충돌 처리
- 서버·클라이언트 배포와 호스팅
- 점수 조작·반복 파밍 대응

서버 기술은 ASP.NET Core + WebSocket으로 결정됐습니다. 기존 서버·클라이언트 연결 구현을 존중합니다.

## P1 — UI와 결과

- 닉네임 허용 문자·중복 허용·게스트 식별 방식
- 랭킹 정렬 기준·동점 순서·내 순위 표시 여부
- 설정 버튼 목록과 메뉴 동작
- 머리 위 게이지가 겹치거나 화면 밖에 있을 때 표시 정책
- 대시 버튼 위치와 쿨타임 표시 방식
- 결과 화면에서 점수 외에 추가할 통계 항목
- 결과 확인 전 연결 유지·관전 여부와 영구 기록 저장 여부
- 탭 비활성화·연결 복구·화면 회전·지원 브라우저 정책

## P2 — 확장

- 희귀 먹이·위험 지역·진화 분기
- 계정·전적 저장·업적·시즌

## 우선 검증할 가설

1. 초식의 먹이 수집과 성장만으로 재미가 유지되는가?
2. 포인터·방향 입력 모두 이동과 회피가 자연스러운가?
3. 자석이 원치 않는 고기 섭취·변이를 강제하지 않는가?
4. 접촉 즉사에 작은 캐릭터가 대응할 여지가 있는가?
5. 성장에 따른 넓은 시야와 표면 기준 흡수 범위가 과도한 우위를 만들지 않는가?
6. 캐릭터가 덮은 모든 타일의 생성 금지가 자원 고갈과 이동을 유도하는가?
7. 초식 과밀 → 굶주림 → 고기 → 변이가 실제 발생하는가?
8. 육식은 고기를 남기지 않는 조건에서 먹이 공급이 유지되는가?
